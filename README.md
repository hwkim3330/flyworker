# 초파리 직원 (flyworker)

**조향을 보정하지 않은 유일한 초파리 커넥톰 구현. LLM 추론 0회.**

🔗 https://hwkim3330.github.io/flyworker/

FlyWire가 공개한 초파리 전뇌 커넥톰 **138,639개 뉴런 · 270만 연결**을
브라우저에서 스파이킹 신경망으로 돌려 게임을 플레이시키고,
버그를 찾아 **100% 재현 가능한 리포트**를 만듭니다.

---

## 먼저 — 이 초파리는 게임을 잘 하지 못합니다

목표를 향해 가지 못합니다. 조향 신호와 빛 방향의 상관계수를 8개 시드로 재면 **0**입니다.
디코더를 세 가지(비율·적응기준선·정류임계) 바꿔봐도 전부 0이었습니다.

그런데 다른 초파리 커넥톰 프로젝트들은 잘 움직입니다. 코드를 열어보면 이유가 나옵니다.

| 프로젝트 | 조향을 누가 하는가 |
|---|---|
| `abgunaydin/webgpu-fly` | *"the connectome does not walk the fly"* — 2,030만 연결이 틱당 스칼라 하나로 줄어 손으로 짠 `sin(t×10Hz)` 보행을 스케일 |
| `Xenova/fruit-fly-simulation` | *"Engineered rate decoder"* · *"movements are illustrative, not validated"* |
| `snedea/flybrain` | 뇌 기여를 `clamp(-0.05, 0.05)` 로 누르고 방향은 `atan2` 로 직접 계산. 주석: *"Steering is primarily handled by behavioral biases"* |
| **이 프로젝트** | **하행뉴런 출력만. 보정 없음** |

정직한 쪽은 그렇다고 적어놨고, 아무도 커넥톰으로 길을 찾게 하지 못했습니다.
그래서 우리는 조향을 손보지 않기로 했습니다. **초파리가 헤매는 모습이 지금 기술의 실제 모습입니다.**

증거는 손상 실험입니다 — 조향 채널 **40개(전체의 0.03%)** 를 자르면 조종이 완전히 죽고,
복구하면 되살아납니다. 스크립트로 보정한 구현은 이 시험을 통과하지 못합니다.

자세한 내용은 [LIMITATIONS.md](LIMITATIONS.md)에 전부 적었습니다.

## 그래서 왜 쓸모가 있는가

**QA 퍼저에게 필요한 건 목표 추적이 아니라 지치지 않는 탐색입니다.**

게임 QA 퍼저에 필요한 건 "사람처럼 그럴듯하되 예측 불가능한 입력"입니다.
순수 난수는 메뉴도 못 넘고, LLM은 비싸서 오래 못 돌립니다.

생물 신경망은 그 사이에 있습니다. 감각 입력에 반응하는 **구조화된 비결정적 정책**을
행렬 연산만으로 제공합니다. **토큰이 한 푼도 들지 않아 무한히 돌릴 수 있습니다.**

## 어떻게 게임을 하는가

```
게임 1인칭 시야 (레이캐스팅, 겹눈 화각 270°)
   ↓  좌/우 눈에 각각 주입 (시각엽 망막위상 좌표로 대응)
LA>ME 라미나→수질 8,029뉴런
   ↓  실제 커넥톰 회로
하행뉴런 1,299개 중 좌우 차등 반응 채널
   ↓
조향 ← →     전진
```

게임의 목표를 **빛**으로 둔 것은 초파리가 빛을 향해 가는 **주광성(phototaxis)** 을
그대로 쓰기 위함입니다. 억지로 붙인 매핑이 아니라 이 뇌가 원래 하는 일입니다.

## 수습 교육

어떤 하행뉴런이 "왼쪽 시야"에 반응하는지는 개체마다 다릅니다.
이름이 알려진 조향 뉴런(DNa01·DNa02)은 **좌우 각 1개뿐**이라 표본이 너무 작습니다.

그래서 고용 직후 좌/우 눈에 번갈아 빛을 비춰 차등 반응하는 하행뉴런을 골라냅니다.
이것이 그 개체의 조향 채널이 됩니다. 집단 부호화입니다. (약 1.5초)

각 채널을 **자기 자신의 균형 조명 반응**으로 나눠 쓰기 때문에,
개체마다 다른 채널 이득 차이가 자동으로 상쇄됩니다.

## 버그를 찾고, 재현한다

감지기는 버그가 어디 심겼는지 **모릅니다.** 증상만 봅니다. 전부 결정적 규칙입니다.

| 증상 | 판정 |
|---|---|
| 화면 정지 | 상태가 90프레임 동안 불변 |
| 끼임 | 300프레임 동안 6×6픽셀을 못 벗어남 |
| 맵 이탈 | 좌표가 맵 밖 |
| 문 잠김 | 열쇠 획득 후 240프레임 경과했는데 문이 닫혀 있음 |
| 진행 불가 | 1800프레임 동안 목표에 더 가까워지지 못함 |

게임은 **(시드 + 입력열)에 대해 결정적**이므로 입력열만 저장하면 버그가 그대로 되살아납니다.
실제 QA에서 가장 괴로운 "재현이 안 되는 버그"가 구조적으로 사라집니다.

> **재현 검증 12/12 완전 일치** (입력을 반올림하면 1500프레임쯤에서 1픽셀씩 어긋나므로 원값을 저장합니다)

## 측정값

| 항목 | 값 |
|---|---|
| 커넥톰 | 138,639 뉴런 / 2,700,513 연결 / gzip **7.45MB** (연결당 2.01B) |
| 시뮬레이션 | 초당 **1,321스텝** (뇌시간 1.3배속), 283만 스파이크/초 |
| 게임 | 165fps |
| 수습 교육 | 1.4초 → 좌채널 20 / 우채널 20 / 활성 하행뉴런 286 |
| 빛 방향 분리도 | **1.158** (왼쪽 -0.409 / 오른쪽 +0.749) |
| 시야 효과 | 목표까지 거리 개선 **44%** (시야 차단 시 35%) |
| 버그 검출 | 10판에 6건, 심어둔 4종 중 3종 |

직원 한 명 = 워커 하나. 커넥톰은 읽기 전용이고 개체별 상태는 0.5MB뿐이라
코어 수만큼 고용해 **진짜 병렬로** 일을 시킬 수 있습니다.

## 정말 커넥톰이 조종하는 게 맞나 — 잘라보면 됩니다

말로 주장하는 대신 손상 실험을 넣었습니다.

| 조작 | 빛 방향 분리도 |
|---|---|
| 정상 | **0.947** |
| 조향 채널 40개 절단 (전체의 0.03%) | **0.000** |
| 복구 | **1.121** |
| 왼쪽 눈 2,000개 절단 | 0.059 (좌우를 못 가림) |

138,639개 중 **40개**만 끊으면 조종이 완전히 죽습니다.
후처리가 만들어낸 신호가 아니라 커넥톰이 실제로 일하고 있다는 뜻입니다.

## 두 번째 근무지 — 둠

*"자기가 만든 장난감에서만 되는 것 아니냐"* 에 답하기 위해 둠을 붙였습니다.
같은 뇌, 같은 조향 채널로 1993년 상용 게임을 조종합니다.

`jacobenget/doom.wasm` 을 씁니다. import 10개 / export 4개뿐인 얇은 인터페이스라
프레임버퍼를 직접 읽고 키를 직접 주입합니다. 셰어웨어 WAD가 모듈에 내장돼 있습니다.

둠에는 심어둔 버그가 없으므로 여기서는 **화면 정지·반복**만 감지합니다.
버그 검출을 증명하는 쪽은 어디까지나 우리 테스트 게임입니다.

## 정직하게 — 한계

- 이 모델은 **커넥톰 구조만** 씁니다. 신경전달물질 종류별 수용체 동역학, 시냅스 가소성,
  뉴런별 형태학적 파라미터는 반영하지 않은 균일 LIF입니다.
- 시냅스 5개 미만 연결을 쳐내 시냅스의 62.7%만 남겼습니다.
  남은 시냅스 가중치를 `0.275 / 0.627 ≈ 0.44` 로 보정했습니다.
- FlyWire는 망막·라미나가 불완전해 광수용체(R1-6) 출력 연결이 평균 1.7개뿐입니다
  (전체 평균 19.5). 그래서 시각 입력을 한 단계 안쪽인 LA>ME에 넣습니다.
- 시야가 도움이 되는 건 측정으로 확인했지만(44% vs 35%), 초파리가 게임을 *잘* 하지는
  못합니다. 이 도구의 목적은 잘 하는 것이 아니라 **넓게 두들겨 보고 깨진 곳을 남기는 것**입니다.

## 개발

```bash
python3 -m venv .venv && .venv/bin/pip install pandas pyarrow numpy
bash tools/00_fetch.sh          # 원본 데이터 (~135MB)
.venv/bin/python tools/pack.py  # 커넥톰 → docs/data/brain.bin
.venv/bin/python tools/meta.py  # 뉴런 역할 → docs/data/meta.json
python3 -m http.server 8877 --directory docs
```
