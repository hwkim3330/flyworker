# Fly Worker

**A QA fuzzer for browser games. One of its policies is a real fruit-fly connectome — and that one loses.**

🔗 Live: https://hwkim3330.github.io/flyworker/ · https://huggingface.co/spaces/kimhyunwoo/flyworker

---

**브라우저 게임을 스스로 플레이해 버그를 찾고, 찾은 것을 그대로 재현하는 QA 퍼저.**
**정책 하나가 초파리 전뇌 커넥톰 138,639뉴런입니다. 그리고 그 정책은 난수에게 집니다.**
**LLM 추론 0회.**

---

## 제품은 프레임워크입니다

```
 ┌── 붙인다 ────────────────────────────────────────────┐
 │ 합성 키 입력 + 프레임버퍼 가로채기.                   │
 │ 게임 소스도, 게임 쪽 인터페이스도 필요 없습니다.       │
 └──────────────────────────────────────────────────────┘
 ┌── 조종한다 ──────────────────────────────────────────┐
 │ 정책 = 화면을 받아 [조향, 전진]을 내놓는 함수 하나.    │
 │ 초파리 커넥톰 · 평활 난수 · 균등 난수 · 직진          │
 └──────────────────────────────────────────────────────┘
 ┌── 판정한다 ──────────────────────────────────────────┐
 │ 결정적 규칙 5개. 어떤 모델도 "이건 버그다"라고         │
 │ 말하지 않습니다.                                      │
 └──────────────────────────────────────────────────────┘
 ┌── 내놓는다 ──────────────────────────────────────────┐
 │ 증거 사진과 재현 파일이 들어 있는 HTML 리포트 한 장.   │
 └──────────────────────────────────────────────────────┘
```

정책은 부품이고 프레임워크가 제품입니다. 그래서 우리 정책이 져도 이 제품은 섭니다.

## 우리 초파리는 집니다 — 재서 싣습니다

같은 프레임워크, 같은 계산량(24,000프레임), 같은 감지기. 정책만 교체했습니다.
난수는 시드를 고정했고 회차를 나눠 평균과 범위를 냅니다.

| 정책 | 맵 탐색률 (평균) | 범위 | 증상 종류 (평균) | 관측된 종류 |
|---|---|---|---|---|
| **초파리 커넥톰** | **34%** | 28–41% | **2.7** | STUCK, OOB, DOORLOCK, FREEZE |
| 평활 난수 | 61% | 57–66% | 3.2 | 다섯 종 전부 |
| 균등 난수 | 50% | 46–52% | 3.6 | STUCK, OOB, DOORLOCK, FREEZE |
| 직진만 (대조군) | 5% | 5–5% | 1.0 | FREEZE |

**버그 개수는 가짜 지표입니다.** 「직진만」이 95건으로 최다인데 전부 같은 정지 하나입니다.
그래서 **탐색률과 증상 다양성**으로 잽니다. 그 기준으로 초파리는 평활 난수에 집니다.

이 결과를 첫 화면에 싣습니다. 숨기면 제품이 정책에 인질로 잡히기 때문입니다.

## 그래도 커넥톰이 정말 조종하는가 — 잘라보면 됩니다

말로 주장하는 대신 손상 실험을 넣었습니다. 화면에서 직접 눌러볼 수 있습니다.

| 조작 | 빛 방향 분리도 |
|---|---|
| 정상 | **0.947** |
| 조향 채널 40개 절단 (전체의 0.03%) | **0.000** |
| 복구 | **1.121** |
| 왼쪽 눈 2,000개 절단 | 0.059 (좌우를 못 가림) |

138,639개 중 **40개**만 끊으면 조종이 완전히 죽습니다.
조향을 스크립트로 보정한 구현은 이 시험을 그대로 통과합니다. 우리 것은 멈춥니다.

| 프로젝트 | 조향을 누가 하는가 |
|---|---|
| `abgunaydin/webgpu-fly` | *"the connectome does not walk the fly"* — 손으로 짠 `sin(t×10Hz)` 보행을 스케일 |
| `Xenova/fruit-fly-simulation` | *"Engineered rate decoder"* · *"movements are illustrative, not validated"* |
| `snedea/flybrain` | 뇌 기여를 `clamp(-0.05, 0.05)` 로 누르고 방향은 `atan2` 로 직접 계산 |
| `nftechie/doomfly` | 도파민 가소성까지 붙였지만 자기 검증을 통과하지 못했다고 적어놨습니다 |
| **이 프로젝트** | **하행뉴런 출력만. 보정 없음** |

## 처음 보는 게임에도 붙습니다

"프레임워크가 제품"이라는 주장은 우리가 본 적 없는 게임에 붙어야만 참입니다.
「Yours」에 HTML 게임을 떨어뜨리면 그 자리에서 붙습니다.

`blob:` 문서는 만든 쪽 출처를 물려받으므로 iframe 안이어도 캔버스를 읽을 수 있습니다.
게임 스크립트보다 먼저 `getContext` 를 가로채야 해서 HTML 맨 앞에 심을 끼워 넣고 blob 으로
다시 만듭니다. 입력은 어디서 듣는지 모르므로 window·document·캔버스 세 곳에 쏩니다.

**안 되는 것도 화면에 그대로 씁니다** — CORS 를 막은 URL(우회 불가), DOM 게임,
오염된 캔버스, 그리고 **외부 표적의 정확 재현**(시드도 내부 상태도 모릅니다).
자세한 것은 [LIMITATIONS.md §2.5](LIMITATIONS.md).

## 버그를 찾고, 재현하고, 리포트를 낸다

감지기는 버그가 어디 심겼는지 **모릅니다.** 증상만 봅니다. 전부 결정적 규칙입니다.

| 증상 | 판정 |
|---|---|
| 화면 정지 | 상태가 90프레임 동안 불변 |
| 끼임 | 300프레임 동안 6×6픽셀을 못 벗어남 |
| 맵 이탈 | 좌표가 맵 밖 (넘은 변 기준으로 한 사건 = 한 건) |
| 문 잠김 | 열쇠 획득 후 240프레임 경과했는데 문이 닫혀 있음 |
| 진행 불가 | 1800프레임 동안 목표에 더 가까워지지 못함 |

게임은 **(시드 + 입력열)에 대해 결정적**이므로 입력열만 저장하면 그대로 되살아납니다.
실제 QA에서 가장 괴로운 "재현이 안 되는 버그"가 구조적으로 사라집니다.

> **재현 검증 12/12 완전 일치** (입력을 반올림하면 1500프레임쯤에서 1픽셀씩 어긋나므로 원값을 저장합니다)

「Download report」를 누르면 **자체 완결형 HTML 한 장**이 나옵니다.
발견 순간의 화면(PNG)과 재현 파일(JSON)이 안에 들어 있어 인터넷 없이 열립니다.

## 어떻게 게임을 하는가

```
게임 1인칭 시야 (레이캐스팅, 겹눈 화각 270°)
   ↓  좌/우 눈에 각각 주입 (시각엽 망막위상 좌표로 대응)
LA>ME 라미나→수질 8,029뉴런
   ↓  실제 커넥톰 회로
하행뉴런 1,299개 중 좌우 차등 반응 채널
   ↓
조향 ← →     전진
```

**수습 교육.** 어떤 하행뉴런이 "왼쪽 시야"에 반응하는지는 개체마다 다릅니다.
이름이 알려진 조향 뉴런(DNa01·DNa02)은 좌우 각 1개뿐이라 표본이 너무 작습니다.
그래서 고용 직후 좌/우 눈에 번갈아 빛을 비춰 차등 반응하는 하행뉴런을 골라냅니다(약 1.5초).
집단 부호화입니다. 각 채널을 자기 자신의 균형 조명 반응으로 나눠 쓰므로
개체마다 다른 이득 차이가 자동으로 상쇄됩니다.

## 측정값

| 항목 | 값 |
|---|---|
| 커넥톰 | 138,639 뉴런 / 2,700,513 연결 / gzip **7.45MB** (연결당 2.01B) |
| 시뮬레이션 | 초당 **1,321스텝**, 283만 스파이크/초 |
| 게임 | 165fps |
| 수습 교육 | 1.4초 → 좌채널 20 / 우채널 20 / 활성 하행뉴런 286 |
| 빛 방향 분리도 | **1.158** (왼쪽 −0.409 / 오른쪽 +0.749) |

직원 한 명 = 워커 하나. 커넥톰은 읽기 전용이고 개체별 상태는 0.5MB뿐이라
코어 수만큼 고용해 **진짜 병렬로** 일을 시킬 수 있습니다.

## 정직하게 — 한계

- **닫힌 고리 시각 주행은 되지 않습니다.** 조향과 빛 방향의 상관계수는 8시드에서 0입니다.
  디코더를 네 가지로 바꿔도 전부 0이었습니다.
- 이유도 측정했습니다. ON 경로는 억제를 통한 부호 반전이라 기저 발화가 없는 모델에선 죽고
  T4는 끝내 울지 않습니다. **커넥톰은 배선을 주지만 동역학은 주지 않습니다.**
- 균일 LIF입니다. 수용체별 동역학도, 가소성도, 뉴런별 파라미터도 없습니다.
- 시냅스 5개 미만 연결을 쳐내 62.7%만 남기고 가중치를 `0.275 / 0.627 ≈ 0.44` 로 보정했습니다.
- FlyWire는 망막·라미나가 불완전해(광수용체 출력 연결 평균 1.7개) 시각 입력을 LA>ME에 넣습니다.

전부 [LIMITATIONS.md](LIMITATIONS.md) 에 있습니다. 실패한 가설과 버린 시도까지 적어뒀습니다.

## 개발

```bash
python3 -m venv .venv && .venv/bin/pip install pandas pyarrow numpy
bash tools/00_fetch.sh          # 원본 데이터 (~135MB)
.venv/bin/python tools/pack.py  # 커넥톰 → docs/data/brain.bin
.venv/bin/python tools/meta.py  # 뉴런 역할 → docs/data/meta.json
python3 -m http.server 8877 --directory docs

node policy_bench.mjs           # 위 정책 비교표를 다시 재본다
```
